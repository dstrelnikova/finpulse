# FinPulse: кейс AI-assisted разработки

## Бизнес-задача и продуктовое решение

FinPulse помогает русскоязычному пользователю ориентироваться в новостях и котировках российского рынка. Это не инвестиционная рекомендация: продукт собирает источники, выделяет факты и риски, а пользователь оценивает их самостоятельно.

Реализованы публичная RSS-лента с индикатором влияния, персональная лента, котировки через MOEX ISS, JWT/RBAC, а также чат с Ollama. GigaChat выполняет структурированный анализ новостей, если включён конфигурацией; при ошибке или отсутствии ключа применяется rules-based fallback.

## Архитектурные решения

React/TypeScript реализует SPA. FastAPI принимает REST-запросы, выполняет Pydantic-валидацию и авторизацию. Application use cases координируют сценарии; SQLAlchemy хранит данные в PostgreSQL; RSS, MOEX, GigaChat и Ollama изолированы в infrastructure. Это модульный монолит, а не микросервисная система. Схема: [architecture.md](architecture.md).

## AI IDE и агенты: подтверждённый workflow этой сессии

1. **Анализ:** прочитаны код, конфигурация, тесты и Git status; стек подтверждён по репозиторию.
2. **План:** приоритеты — безопасная конфигурация, проверяемость, документация и CI.
3. **Реализация:** development `.env.example` переведён на placeholders; CI получил dependency audit и job для уже существующих Playwright-сценариев.
4. **Проверка:** выполняются доступные backend/frontend/e2e проверки, результаты фиксируются в readiness report.
5. **Review:** агент не публикует секреты, не меняет архитектуру и не делает push/deploy. Нужен обычный human review перед merge.

Личный вклад автора в исходную разработку следует сформулировать самостоятельно: этот документ не приписывает пользователю действия, которых нет в репозитории или текущей сессии.

## Тестирование, безопасность и ограничения

Pytest покрывает auth, RSS, MOEX, fallback и API-слой; Vitest проверяет frontend; Playwright проверяет публичные новости, login/logout и администрирование на controlled API responses. Secrets приходят из окружения; `.env` игнорируется; CI запускает dependency audit. Автоматические проверки не доказывают отсутствие всех дефектов и уязвимостей.

Ограничения: нет версионированных миграций, e2e не подтверждают полный Docker-контур, а качество GigaChat/Ollama зависит от внешних сервисов. Дальше разумно добавить migrations, observability, contract fixtures и Docker smoke test без реальной модели.
