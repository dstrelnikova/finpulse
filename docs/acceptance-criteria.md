# Критерии приёмки

Критерии сгруппированы по пяти ключевым функциям. Они описывают проверяемое поведение из [требований](requirements.md).

## Функция 1 — Публичная рыночная информация

### AC-01 — Публичная лента

**Related requirement:** FR-01, NFR-03
**Given** backend доступен и в БД есть подходящие публичные записи
**When** клиент вызывает `GET /public/news?limit=10`
**Then** ответ имеет HTTP 200, JSON-массив содержит не более 10 элементов `NewsBlockOut` и не содержит отфильтрованных записей.

### AC-02 — Отсутствующая новость

**Related requirement:** FR-02
**Given** публичной новости с ID 404 нет
**When** клиент вызывает `GET /public/news/404`
**Then** ответ имеет HTTP 404 и `detail="News item not found"`.

### AC-03 — Недоступность MOEX

**Related requirement:** FR-03, NFR-03
**Given** MOEX ISS не отвечает или возвращает ошибку
**When** клиент вызывает endpoint котировок с `limit=20`
**Then** ответ имеет HTTP 200, `fallback=true`, содержит 20 тикеров и nullable ценовые поля; необработанного HTTP 500 нет.

## Функция 2 — Аутентификация

### AC-04 — Регистрация и вход

**Related requirement:** FR-04, FR-05
**Given** email ещё не зарегистрирован и body соответствует schema
**When** гость регистрируется, затем входит
**Then** пользователь сохранён с хешем пароля, login возвращает непустые access/refresh JWT, а `/me` с access token даёт HTTP 200.

### AC-05 — Невалидные credentials и ввод

**Related requirement:** FR-04, FR-05, NFR-02
**Given** существует пользователь
**When** отправлен неверный пароль
**Then** login возвращает HTTP 401 без JWT; **When** имя короче 2 или пароль короче 6 символов — регистрация возвращает HTTP 422 и пользователь не создаётся.

### AC-06 — Ротация refresh token

**Related requirement:** FR-06
**Given** refresh token валиден и совпадает с сохранённым в БД
**When** клиент вызывает `/auth/refresh` дважды с исходным token
**Then** первый запрос возвращает новую пару, второй с уже заменённым исходным token возвращает HTTP 401.

### AC-07 — Logout

**Related requirement:** FR-07
**Given** пользователь вошёл и refresh token сохранён
**When** он вызывает `/auth/logout` с валидным access token
**Then** ответ имеет HTTP 200, а последующий refresh с ранее сохранённым token — HTTP 401.

## Функция 3 — Профиль

### AC-08 — Нормализация профиля

**Related requirement:** FR-08, FR-15
**Given** пользователь аутентифицирован и имеет permission
**When** он отправляет `tickers=[" sber ","SBER"]` и два одинаковых допустимых сектора
**Then** HTTP 200 содержит один `SBER` и по одному значению каждого сектора; остальные не переданные поля не изменены.

### AC-09 — Недопустимое значение профиля

**Related requirement:** FR-08, NFR-02
**Given** пользователь аутентифицирован
**When** PATCH содержит неизвестный сектор или тикер вне regex
**Then** ответ HTTP 422, а ранее сохранённый профиль не изменён.

## Функция 4 — AI-чат

### AC-10 — Успешный обмен

**Related requirement:** FR-09, FR-10, FR-11
**Given** пользователь имеет `chat:use`, Ollama доступен и возвращает приемлемый ответ
**When** отправлено сообщение длиной 1–4000 символов
**Then** HTTP 200 содержит `answer` и default `chat_id`, а история содержит сохранённые user/FinPulse сообщения этого пользователя.

### AC-11 — Ошибка чата

**Related requirement:** FR-09, NFR-02
**Given** пользователь имеет доступ
**When** message пуст или длиннее 4000 символов
**Then** ответ HTTP 422 без вызова Ollama; **When** Ollama недоступен — HTTP 503 `CHAT_MODEL_UNAVAILABLE` без фиктивного успешного ответа.

## Функция 5 — RBAC-администрирование

### AC-12 — Авторизация и роли

**Related requirement:** FR-12, FR-13
**Given** обычный пользователь и администратор существуют
**When** обычный пользователь читает `/admin/users`
**Then** ответ HTTP 403; **When** администратор назначает существующие роли — HTTP 200 и связи заменены; неизвестная роль даёт HTTP 400 без частичного изменения.

### AC-13 — Персональная лента без GigaChat

**Related requirement:** FR-14, NFR-03
**Given** пользователь имеет `news:list`, профиль сохранён, а GigaChat отключён или недоступен
**When** он вызывает `GET /news/feed`
**Then** backend использует RSS/cache и rules-based анализ, возвращает валидный `NewsBlockOut[]` либо пустой массив и не возвращает необработанный HTTP 500 из-за GigaChat.
